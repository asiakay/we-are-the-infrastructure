# Application

The application is the operational implementation of WE ARE THE INFRASTRUCTURE.

It should emerge from validated methods and cases rather than dictate them.

## Initial product modes

**LEARN → INVESTIGATE → MAP → PLAN → BUILD → REFLECT**

## Candidate domain objects

- Source
- Claim
- Evidence
- Insight
- Question
- Actor
- Institution
- Relationship
- Asset
- Resource
- Constraint
- System
- Opportunity
- Risk
- Capability
- Strategy
- Project
- Action
- Outcome
- Lesson

These objects should eventually connect knowledge to action: a knowledge graph capable of becoming an action graph.

## Technical direction

Target: an offline-capable Progressive Web Application with GitHub as the source/versioning layer and Cloudflare infrastructure evaluated for application delivery, compute, persistence, and storage.

No technical choice is canonical until the first real case establishes what the software actually needs to do.
