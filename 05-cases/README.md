# Cases

Cases are where the framework meets real conditions.

The first validation target is one complete vertical slice:

**Situation → Observe → Verify → Map → Diagnose → Leverage → Sequence → Build → Act → Reflect → Expand**

Cases should preserve both successful and failed interventions. Their purpose is not to make the framework look correct; their purpose is to produce evidence that improves it.

## User 0 principle

Before building a large application, the framework should be exercised on a real problem by its own creator. Friction encountered during that process becomes evidence for methods, templates, data structures, and eventual product requirements.
